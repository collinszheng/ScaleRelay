# ScaleRelay

> 把小米米家体脂秤 **S400** 的体重数据转发进 Android **健康数据共享（Health Connect）**。

## 为什么需要它

小米自家 App **不会**把秤的数据写进 Health Connect，所以任何从 HC 读体重的应用
（比如 [体重日记 / WeightDiary](../WeightDiary)）对这台秤都是读不到的。

ScaleRelay 直连秤、把体重写进 HC，**体重日记那边一行都不用改**。

## 只做三件事

```
配置（MAC + 登录令牌 + 授权 HC）  →  BLE 收数  →  写 HC
```

**明确不做**：历史记录、图表、多用户、自己的体重数据库、额外体成分字段。
那些体重日记全都有，而且在真机上验证过。造第二个体重 App 是纯粹的浪费。

具体砍掉了什么（相对 `三工具整合开发方案.docx` §8/§10 的方案）：

| 文档要求 | 本项目 |
|---|---|
| Room 存用户资料、测量记录、同步状态 | **不做**。配置用 `SharedPreferences`（就三个值），测量不落库 —— HC 就是存储 |
| 8 个页面（引导/Token 教程/设备/资料/授权/主页/历史/设置） | **1 个页面** |
| 申请 6 个 HC 写权限 | **只申请 1 个**：`WRITE_WEIGHT` |
| 移植 openScale 全部体成分公式 | **不做**。体重日记的数据模型只有体重与体脂率，多算的没有出口 |
| 多用户按参考体重自动匹配 | **不做**，单用户自用 |

## 它是怎么工作的

```
小米 S400  ──BLE GATT（Mi Home v2 认证 + AES-CCM）──▶  ScaleRelay
                                                          │
                                                          ▼
                                                  Health Connect
                                                          │
                                                          ▼
                                                     体重日记
```

- 常驻**前台服务**监听，收到「最终测量」就写入 HC
- 写入用**稳定的 `clientRecordId`**（`s400-<mac>-<时间戳>-weight`），
  所以重试/重写是**更新同一条**而不是新增 —— 体重日记靠 HC 的 `metadata.id` 去重，这样才幂等
- **同一时刻的体重与体脂会用同一个 `time` 与 `zoneOffset`**（本轮只写体重，
  但接口按体重日记 `docs/08` 的配对契约设计，将来补体脂不用改结构）

### ⚠️ 为什么不走 BLE 广播（这条路我实测过，是死的）

网上有资料说 S400 会把测量值放在 BLE 广播里。**实测证明不会**：
在真机上抓了 206 个 `0xFE95` 广播，`frameControl` 的 object 位**一次都没置起过**，
期间在秤上称了三次。所有广播都是「状态包」（11 字节，只含 MAC）。

测量值**只通过 GATT 认证后的加密 CMTP 通道**下发。
相关证据与协议细节见 `../docs/s400-bridge-design.md`。

**因此这个 App 必须独占与秤的 BLE 连接** —— 米家 App 一开就会把连接抢走，
所以使用前要**完全退出米家**（不是切到后台，是在最近任务里划掉）。

## 使用步骤

### 1. 取秤的 MAC 与登录令牌

1. 临时把秤加进「米家 / Xiaomi Home」，**并完成至少一次称重**
2. 在电脑上运行 [Xiaomi-cloud-tokens-extractor](https://github.com/PiotrMachowski/Xiaomi-cloud-tokens-extractor)，
   用同一个小米账号登录
3. 找到 `Mijia Body Composition Scale S400`，抄下 **MAC** 与 **TOKEN**
4. **在米家里「删除设备」**（不是恢复出厂设置）

> ⚠️ **不要给秤恢复出厂设置，也不要再次加回米家** —— 那会换掉登录令牌，得重新提取。
> 小米账号登录可能遇到 2FA；工具是第三方的，与小米无关联。

### 2. 配置

填 MAC 与令牌 → 保存 → 授权「健康数据共享」的写入体重 → 开始监听。

### 3. 日常

**退出米家** → 赤脚站上秤 → 等读数稳定 → 体重自动进 HC。

> ⚠️ **接入后的第一次称重不会出现在体重日记里，要称第二次才会进去。这是设计，不是故障。**
>
> 原因：体重日记有一个时间边界规则 —— 它会丢弃「时间早于它库里最后一条手动记录」的
> HC 记录（`docs/08 §4.3`）。而它要求你先手动记一条自己的体重作为接入前置
> （那条记录同时提供边界与异常过滤的锚点），于是边界被推到了「刚才」，
> 早于它的记录一律不收。第二次称重落在边界之后，就正常进来了。
>
> 实测确认：第一次 → `已同步 0 条`；第二次 → `已同步 1 条`，历史里出现
> `61.0 kg ↓0.5 · 今天 19:31 · 体脂秤`。

## 隐私

- **清单里没有 `INTERNET` 权限** —— 这个 App 在系统层面就没有联网能力（有脚本断言，见下）
- 登录令牌只存在本机私有目录（`allowBackup=false`，不进云备份），**不写日志、不显示在界面上**
- 只申请 `WRITE_WEIGHT` 一项 HC 权限，**不读取任何健康数据**
- 不收集、不上传任何东西

## ⚠️ 秤不保存历史 —— 以及本 App 因此做了什么

**S400 不存历史。** 它只在被踩的那一刻、实时把数据推给「当时连着」的客户端
（实测证据见 `../docs/s400-bridge-design.md §7.0.1`）。

所以数据丢失有两类，性质完全不同：

| 丢失点 | 能否挽救 |
|---|---|
| **App 没在运行**时的称重 | ❌ **救不了**。数据从没到过 App，秤那边也拿不回来 |
| **App 在运行、但写 HC 失败** | ✅ **能救**。数据已经到过 App |

第二类已由**持久化重试**覆盖：收到最终测量**先落盘**，写 HC 成功后再删；
失败则留在队列里，在**服务启动时**、**下次写成功后**、以及一个**退避定时器**上重试。
界面上会显示「有 N 条称重还没写进健康数据」，正常情况下这个数字恒为 0。

> 已做反向验证：故意撤销 HC 权限 → 称重 → 确认数据落盘未丢 →
> 恢复权限 → 自动补写成功 → 去 HC 里核实记录确实存在。

## 构建

```powershell
$env:JAVA_HOME = 'E:\Android\Android Studio\jbr'
cd E:\adev\ScaleRelay
.\gradlew.bat assembleDebug
```

产物：`app\build\outputs\apk\debug\app-debug.apk`

> **本机环境注记**：Gradle 需要写 `~/.gradle`。本工作区把它重定向到
> `E:\adev\_gradle_home`（`$env:GRADLE_USER_HOME`），避免每次都要提权。
> 另外本沙箱下 JVM 的 `Files.isWritable()` 对可写目录会返回 `false`，
> 导致 Gradle 在配置阶段报 `Configuring project ':app' without an existing directory is not allowed`
> —— 那是**假否定**（实测实际写入成功），给构建命令提权一次即可绕过。

## 验证

已完成的验证（都是真机或离线可复跑的，不是「读代码推断」）：

| 项 | 结果 |
|---|---|
| BLE 广播路线是否存在测量数据 | ❌ **证伪**：206 个广播 object 位恒为 0 |
| GATT 认证（Mi Home v2） | ✅ 一次通过，`remoteInfo` HMAC 校验通过 |
| CMTP 分帧 + AES-CCM 解密 | ✅ 收到 35 条 LIVE + 2 条 FINAL |
| FINAL 测量解析 | ✅ 60.9kg / 高阻抗 463.0Ω / 低阻抗 426.0Ω / profileId=1 |
| 自研 HKDF vs BouncyCastle | ✅ 16/32/40/64/100 字节输出**逐字节一致** |
| 编译 | ✅ `assembleDebug` 通过 |
| 清单无 `INTERNET` | ✅ 实测断言通过 |
| HC rationale 两个 intent-filter | ✅ 都在（少了 HC 会 `finishing`、弹窗不出现） |
| **端到端：称重 → HC → 体重日记** | ✅ **已跑通**。HC 里见到 `19:31 • ScaleRelay • 134.5 lb`（=61.0kg）；体重日记历史出现 `61.0 kg ↓0.5 · 今天 19:31 · 体脂秤` |
| 前台服务常驻 | ✅ 离开 App + 息屏 30 秒后进程仍在，`isForeground=true`、`types=0x10`（connectedDevice）、通知 `ONGOING_EVENT｜NO_CLEAR` |
| 自动认证 | ✅ 全程 3 秒、无人工干预：连接 → 服务发现 → 订阅 → `remoteInfo HMAC 校验通过` → READY |
| **持久化重试**（反向验证） | ✅ 撤销 HC 权限 → 称重 → 数据落盘未丢 → 恢复权限 → **自动补写成功**，HC 里核实到该条记录 |

**一个实测到的、看起来像 bug 的现象**：接入后**第一次称重不会被体重日记接收**，
要称第二次才出现。原因是体重日记的时间边界规则（丢弃早于「最后一条手动记录」的 HC 记录），
而它的强制前置步骤要求你先手动记一条 —— 边界因此被推到「刚才」。
详见 `../docs/s400-bridge-design.md §7.0`。
